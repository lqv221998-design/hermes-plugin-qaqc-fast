# Module guide — portable QAQC Fast

This is a bounded navigation/read recipe guide, not the organization's complete QAQC procedure or the recipient's permission inventory. It is sufficient to operate the shipped three modules without separately installed skills. QAQC server-side ACL and the recipient's own browser login decide access.

## Resolve a request
1. Ask only if the exact requested project is missing and cannot be obtained from the user's request/evidence. Never choose an author's project or the currently selected project by default.
2. capabilities describes code support, not permission grants. pages discovers observed page IDs; neither confirms account/project.
3. inspect verifies the locally bound account display name and the project header. URL menu IDs are not project IDs. Display names are not unique principal IDs.
4. open_module/read_list resolves current live controls; no cached element ID, guessed deep link, hidden API or alternate account. A missing menu or denial stops; it does not prove there are no records.
5. Present the source URL, project, observed time and coverage. Current-page results do not cover pagination, image interpretation, SharePoint contents or complete registers. Data may still be loading. Truncation is explicitly partial.

## Each recipient separately
The recipient sets their own binding and grants access only to their dedicated chrome_qaqc connector. Empty binding, wrong account, wrong project, unverifiable header, permission denial and host failures are pending/stop states. Never copy cookies, browser profiles, passwords, trust grants or account settings between installations. Do not multiplex several users through one credential-bearing browser. Do not lower trust, switch accounts or retry a denied operation to bypass policy.

## Unknown modules or writes
RC can navigate additional observed menu paths and headings, but that is not live acceptance or a write grant. Read the main operations skill for typed expanded verbs, owned TEST scope, readiness, discipline, lossless artifacts and workflow gates. No arbitrary URL/script or hidden API; unknown/denied UI stays pending.
